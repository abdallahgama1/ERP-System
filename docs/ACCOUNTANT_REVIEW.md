# Accountant Review Guide — Count It, Keep It ERP

This document is a factual, code-verified accounting reference for a human accountant or financial controller reviewing **Count It, Keep It** (single-company deployment, base currency **EGP**). Every journal rule, account code, report calculation, and control check below matches the current codebase and is verified in CI via `npm run demo:ledger` and the automated integration test suite.

---

## 1. General Ledger Architecture & Posting Controls

- **Double-Entry Enforcement ([gl.service.ts](file:///c:/Users/mohamed/Desktop/count-it-keep-it/backend/src/services/gl.service.ts#L208-L289)):** `validateAndNormalizeJournalLines()` rejects any journal entry with fewer than 2 lines, non-positive totals, or an out-of-balance base-currency residual exceeding `0.05 EGP`. For automated operational entries via `postMappedJournal()`, residuals between `0.0001` and `0.05 EGP` (e.g., FX or tax rounding pennies) are automatically plugged to `5900 Purchase Price & Rounding Variance` (`rounding_variance`).
- **Period Lock Enforcement ([gl.service.ts](file:///c:/Users/mohamed/Desktop/count-it-keep-it/backend/src/services/gl.service.ts#L291-L331)):** Every call to `postJournalEntry()` executes `assertPeriodOpen()`, blocking postings into any period with `status = 'locked'` (`400 FISCAL_PERIOD_LOCKED`) or any fiscal year with `status = 'closed'` (`400 FISCAL_YEAR_CLOSED`).
- **Monetary Precision ([helpers.ts](file:///c:/Users/mohamed/Desktop/count-it-keep-it/backend/src/db/helpers.ts#L27-L31)):** Amounts are stored as `NUMERIC(18, 4)` (`fx_rate` as `NUMERIC(12, 6)`), and balanced against `debit_base` / `credit_base` in the company's base currency (**EGP**).
- **Immutability & Reversals ([gl.service.ts](file:///c:/Users/mohamed/Desktop/count-it-keep-it/backend/src/services/gl.service.ts#L543-L590)):** Posted journal entries are never edited or deleted. Voiding an operational document calls `reverseJournalEntriesForSource()` / `reverseSingleJournalEntry()`, creating a new `status = 'posted'` entry (`sourceType = 'reversal'`) with swapped debits and credits and marking the original entry `status = 'reversed'` (`reversed_entry_id` linked).
- **Accountant Classification Confirmation (FX & Asset Disposal Gains/Losses):**
  > [!IMPORTANT]
  > Accounts `5600 Realized FX Gain & Loss`, `5610 Unrealized FX Gain & Loss`, and `5710 Gain & Loss on Asset Disposal` are seeded with `account_type = 'expense'` (`normal_balance = 'debit'`). On the Profit & Loss statement (`getProfitAndLoss()`), net credit gains in these accounts therefore appear as **negative Operating Expenses** (reducing total operating expenses and increasing Net Income) rather than in a separate "Other Income / Expense" section below Operating Profit. **The reviewing accountant should confirm whether this P&L presentation is acceptable for statutory reporting or whether these lines should be reclassified below Operating Profit.**

## 4. Controlled Reopening of a Closed Fiscal Year

- **Controlled Admin Action (`POST /api/accounting/fiscal-years/:id/reopen`):** Implemented in [gl.service.ts](file:///c:/Users/mohamed/Desktop/count-it-keep-it/backend/src/services/gl.service.ts) (`reopenFiscalYear`) and [accounting.ts](file:///c:/Users/mohamed/Desktop/count-it-keep-it/backend/src/routes/accounting.ts):
  1. Restricted strictly to **`admin`** role (`requireRole("admin")`).
  2. Requires a written `reason` (`min 5` characters, validated by `reopenFiscalYearSchema`).
  3. Blocks reopening if any **later** fiscal year is already closed (`409 LATER_FISCAL_YEAR_CLOSED`).
  4. Inside one PostgreSQL transaction: reopens the fiscal year and its child periods, **reverses** the original `year_end_close` journal entry **dated at `fy.endDate`** (never deleting rows), marks the original closing JE `status = 'reversed'`, and appends a hash-chained `fiscal_year.reopened` entry to `audit_logs`.
  5. After posting missed adjustments, run `POST /api/accounting/fiscal-years/:id/close` to re-close and re-lock all periods with the updated net income transferred to `3100 Retained Earnings`.
  6. Verify `GET /api/audit-logs/verify` returns `valid: true`.
- **Standard GAAP/IFRS Guidance:** Even though controlled reopening is supported for premature closes prior to statutory filing, once financial statements or tax returns have been issued, prefer leaving the prior year closed and posting a prior-period adjustment on the first day of the current open fiscal year against `3100 Retained Earnings`.

### 5.2 What Happens If an Existing Chart of Accounts Already Uses `3100`, `5600`, `5610`, etc.?

1. **No Silent Wrong-Type Binding (Fixed Forward in Migration `0012` & `ensureAccountingDefaults`):**
   - `ensureAccountingDefaults()` ([gl.service.ts](file:///c:/Users/mohamed/Desktop/count-it-keep-it/backend/src/services/gl.service.ts#L89-L115)), `seedCompanyDefaults()` ([permissions.ts](file:///c:/Users/mohamed/Desktop/count-it-keep-it/backend/src/auth/permissions.ts#L346-L368)), and forward migration [0012_accounting_mapping_type_guard.sql](file:///c:/Users/mohamed/Desktop/count-it-keep-it/backend/drizzle/migrations/0012_accounting_mapping_type_guard.sql) all verify **`account_type`** before binding any `gl_account_mappings` key.
   - If a custom COA already uses `3100` as a `liability`, `5600` as an `asset`, or `5610` as `revenue`, the existing account is preserved untouched and the mapping is **NOT** silently bound.
   - `PUT /api/accounting/mappings` also rejects binding any account whose `account_type` does not match the mapping's required type (`400 INVALID_MAPPING_ACCOUNT_TYPE`).
2. **Admin Accounting Setup Health Check (`GET /api/accounting/setup-health`):**
   - Surfaces every missing, inactive, or type-mismatched mapping with the colliding account details and explicit instructions to create a dedicated account of the required `account_type` and bind it via `PUT /api/accounting/mappings`.
3. **Report Literal Code Checks to Keep in Mind:**
   - `getProfitAndLoss()` classifies `code === "5000"` as `cogsTotal`; `getCashFlowStatement()` includes `1000`/`1010`/`1020` (and children of `1000`) in Cash and checks `glMap` **or** `1500`/`1510`/`5700`/`5710` for Fixed Assets/Depreciation/Disposal; `createTreasuryAccount()` attaches new `1030+` sub-accounts under parent `"1000"` (skipping any existing codes). Avoid repurposing those specific codes for unrelated categories.
